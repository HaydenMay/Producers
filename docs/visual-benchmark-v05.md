This is technical-art evidence, not a design decision. The reference concepts and latest owner screenshots were not present in this checkout, so their match has **not** been assessed. ## Source and reproduction

- `assets/blender/studio_assets.blend`: editable original assets and a preview camera/lights. The saved worker is positioned at the desk for preview; its export origin is reset to the floor under the chair.
- `tools/blender/generate.py`: rebuilds the original geometry, materials, hierarchy, source file, GLBs and preview image from scratch. **This overwrites the blend file**, so do not run it over manual edits.
- `tools/blender/export.py`: exports the current edited `.blend` without regenerating it. From the repository root on this machine:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background assets/blender/studio_assets.blend --python tools/blender/export.py
npm run build:game
```

Use your installed Blender path if different. The two exports were byte-identical on consecutive runs of `export.py` using Blender 5.2.0 LTS. Export is GLB, selected root and descendants only, applied modifiers, Y-up conversion, with no cameras/lights or external images. Preview render can be regenerated by opening the `.blend` and rendering its camera. Meshes were grouped by material and parent pivot to reduce draw calls; edit mode can still modify their constituent geometry. The source, materials, geometry and script are original to this benchmark; no third-party art or textures were used.

Blender is right-handed with Z up. The modeled worker faces Blender +Y; its workstation desk center and floor are the local origin. glTF/Three.js are right-handed with Y up, so the exported person faces local −Z, the floor is Y=0, and one unit is approximately one metre. `desk_root` includes `chair_root`; `worker_root` is separately placed at local `(0, 0, 1.15)` in Three.js. The scene rotates each station by −90° around Y. `head_pivot`, `arm_l_pivot`, and `arm_r_pivot` own the independently animated parts. `hair_swept` is a conditional child of the head. Screen orientation, contact with the chair, and location were checked in the browser images, not just inferred from axes.

`src/game/office/imported-station.ts` clones the scene graph for each employee but shares geometry and untinted materials. It clones the named `shirt`, `pants`, `skin`, and `hair` materials per employee, applies the existing ID-derived palette, and selects `hair_swept` by the existing appearance value. The renderer owns and disposes its clones and loaded shared resources. `scene.ts` retains the procedural workstation while loading and on failure; it swaps all instances only after both models load and validates their pivot names. Reduced-motion uses the existing motion gate. To add a station, use the same desk/worker roots with a new stable staff ID; to add a hair option, extend the Blender head hierarchy and `appearanceFor`, then re-export and verify the named nodes and all previews. Do not put simulation logic into these assets.

## Actual measurements and checks

Chrome 157.0.8103.51, Windows desktop, NVIDIA GeForce RTX 4060 via ANGLE D3D11, 1440 × 900, pixel ratio 1, WebGL2. `renderer.info` figures include rendering/shadow passes and vary with culling and viewport. The rough frame interval is the mean of 120 `requestAnimationFrame` intervals, **not** a GPU benchmark; it is affected by refresh rate and headless browser scheduling.

| Seats | Draw calls | Triangles | Mean frame interval |
| ---: | ---: | ---: | ---: |
| 2 | 266 | 70,608 | 7.59 ms |
| 4 | 372 | 105,240 | 7.71 ms |
| 6 | 478 | 139,776 | 7.62 ms |
| 8 | 584 | 174,888 | 7.69 ms |

The baseline two-seat desktop readout was 380 calls / 79,440 triangles. The eight-seat desktop did not show a measurable slowdown in this short observation, but 584 calls plus shadows are a concrete risk on a phone. A desktop portrait viewport is not a phone performance test. Test real iPhone Safari, including thermal behavior and the drawer, before treating the eight-seat preview as mobile-ready.

- `npm run typecheck`, targeted office/model tests, and `npm test`: passed: 32 files, 228 tests in the full suite.
- `npm run build:game`: passed; Vite warns that the JS chunk exceeds 500 kB (770.5 kB uncompressed), a remaining load-time risk.
- `npm run ledger:check`: 207 audit entries mapped, 229 ledger rows, 0 problems; 622 parameters match. On this Windows checkout, the existing scripts compare LF lines literally: the ledger, audit, register and one legacy CSV fixture had to be temporarily normalized to LF before checking. Their contents were restored afterward; no ledger decision changed.
- Chrome exercised start, pause, stepping, casting, distribution and release at week 30. Blocking both GLBs left the procedural office and production controls working. A reduced-motion browser context rendered the fallback. The built `/Producers/` preview returned HTTP 200 for both GLBs and showed the eight-seat scene without console errors.
- The previously existing preview configuration used `/` when serving a build even though the bundle requested `/Producers/`; preview now uses the same base as the build. Feature-branch changes do not deploy the live GitHub Pages site.

## Assessment

**Three.js + Blender is viable with concrete risks.** The editable source, independently re-exported GLBs, runtime variants and pivots, actual browser screenshots, and desktop 2–8-seat previews demonstrate the pipeline. The high eight-seat draw count, chunk size, small portrait faces, missing owner reference images, and untested real iPhone performance prevent a stronger art or mobile-readiness claim. The smallest next action is to compare the supplied reference images and review the feature build on the owner's iPhone, then profile and batch further only if the device shows a real bottleneck.
